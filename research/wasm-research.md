# WebAssembly-Based Sandboxes for AI Agents — Research

> Researched: 2026-02-25

This document catalogs WebAssembly (Wasm) runtimes, frameworks, and projects relevant to sandboxing AI agent workloads. Projects are organized into tiers based on their directness of relevance to agent sandboxing.

---

## Tier 1: Purpose-Built for AI Agent Sandboxing

### Wassette (Microsoft)
- **Repo**: https://github.com/microsoft/wassette
- **Stars**: ~846
- **Description**: Security-oriented runtime that runs WebAssembly Components via Model Context Protocol (MCP), built by Azure Core Upstream team.
- **Agent Relevance**: Direct
- **Evidence**: Purpose-built for AI agents. Agents autonomously fetch Wasm Components from OCI registries and execute them as MCP tools. Works with GitHub Copilot, Claude Code, Cursor, Gemini CLI.
- **Key Features**: Deny-by-default permission system; built on Wasmtime; fine-grained interactive resource access control; zero runtime dependencies; Rust standalone binary; WIT-based typed interfaces exposed as MCP tools.
- **Status**: Active (released August 2025, under active development by Microsoft)

### amla-sandbox
- **Repo**: https://github.com/amlalabs/amla-sandbox
- **Stars**: ~309
- **Description**: WASM sandbox with capability enforcement for AI agents — QuickJS inside WASM with controlled tool access.
- **Agent Relevance**: Direct
- **Evidence**: Explicitly designed for agent code execution. Replaces subprocess/exec() calls in agent frameworks. Supports capability tokens, audit trails, and multi-agent authority attenuation.
- **Key Features**: QuickJS in WASM; sandboxed virtual filesystem; no network/shell escape; ~0.5ms load after first compile; 13MB static binary; capability-based security with unforgeable tokens; deterministic replay; context budget control.
- **Status**: Active

### llm-wasm-sandbox
- **Repo**: https://github.com/ThomasRohde/llm-wasm-sandbox
- **Stars**: ~1
- **Description**: Production-grade security sandbox for executing untrusted Python & JavaScript code generated by LLMs using WebAssembly and WASI.
- **Agent Relevance**: Direct
- **Evidence**: Built specifically for LLM-generated code execution. Includes MCP server support for standardized tool use in AI applications.
- **Key Features**: Bundled CPython 3.11 and QuickJS-NG WASM runtimes; multi-layered defense (WASM memory safety + WASI capabilities + resource limits); MCP server with execute_code and list_runtimes tools; Wasmtime-based.
- **Status**: Active (new project, low adoption)

### mcp-run-python (Pydantic)
- **Repo**: https://github.com/pydantic/mcp-run-python
- **Stars**: ~189
- **Description**: MCP server to run Python code in a Pyodide/Deno sandbox, providing secure execution for AI agent code.
- **Agent Relevance**: Direct
- **Evidence**: Built by Pydantic for LLM code execution. MCP-native. Used with Claude Code, Claude Desktop, and PydanticAI. Being succeeded by Monty for better security/performance.
- **Key Features**: Pyodide (CPython in WASM) running inside Deno; automatic dependency detection; captures stdout/stderr/return values; two-step install (write deps, then read-only execution).
- **Status**: Active (but team shifting focus to Monty)

### Sandbox MCP (Cosmonic)
- **Repo**: https://github.com/cosmonic-labs/openapi2mcp (related tooling)
- **Stars**: N/A (product/plugin for wasmCloud)
- **Description**: Free open-source plugin for CNCF wasmCloud that generates standards-compliant MCP servers as secure WebAssembly components.
- **Agent Relevance**: Direct
- **Evidence**: Explicitly designed for "safely extending LLMs and agentic systems." Turns OpenAPI specs into sandboxed MCP servers with capability-driven permissions.
- **Key Features**: Generates MCP servers from OpenAPI specs; CNCF wasmCloud-powered; built-in auth (API Keys, OAuth 2.0, mTLS, JWT); virtualized filesystems; fine-grained I/O controls; scale-to-zero.
- **Status**: Active (website: sandboxmcp.ai)

## Tier 2: General-Purpose Wasm Runtimes Used for Agent Sandboxing

### Wasmtime (Bytecode Alliance)
- **Repo**: https://github.com/bytecodealliance/wasmtime
- **Stars**: ~17,600
- **Description**: Fast, secure, standards-compliant WebAssembly runtime with Cranelift JIT/AOT compilation.
- **Agent Relevance**: Indirect (foundation layer)
- **Evidence**: Underlies Wassette, amla-sandbox, llm-wasm-sandbox, and many other agent-sandboxing projects. Formally verified for memory safety. Used in wasmtime-py executor for smolagents.
- **Key Features**: Cranelift compiler; WASI support; Component Model support; 2GB guard regions; LTS releases; language bindings for Rust, C, Python, Go, .NET, Ruby; capability-based filesystem access.
- **Status**: Active (v42.0.0, monthly releases, backed by Bytecode Alliance — Microsoft, Google, Red Hat, Amazon)

### WasmEdge (CNCF)
- **Repo**: https://github.com/WasmEdge/WasmEdge
- **Stars**: ~11,470
- **Description**: Lightweight, high-performance Wasm runtime — the fastest Wasm VM and first official CNCF WebAssembly sandbox project.
- **Agent Relevance**: Indirect (with direct AI extensions)
- **Evidence**: LlamaEdge framework runs GenAI models (LLM, speech-to-text, text-to-image, TTS) on WasmEdge. Supports wasi-nn for ML inference. Key use case is safely executing user-defined or community-contributed code as plug-ins.
- **Key Features**: CNCF Sandbox project; LlamaEdge for LLM inference; wasi-nn support; GGUF model format; <30MB runtime; runs on x86/ARM/Apple/RISC-V/NVIDIA GPUs; Kubernetes integration.
- **Status**: Active (CNCF Sandbox, Health Score 72)

### Wasmer
- **Repo**: https://github.com/wasmerio/wasmer
- **Stars**: ~20,000
- **Description**: Blazing fast and secure WebAssembly runtime enabling lightweight containers to run anywhere.
- **Agent Relevance**: Indirect
- **Evidence**: General-purpose Wasm runtime with strong sandboxing. Secure by default (no file, network, or environment access unless enabled). Used in blockchain and edge computing. No direct agent-specific tooling.
- **Key Features**: WASIX and WASI support; pluggable compilers (Singlepass, Cranelift, LLVM); SDKs for 10+ languages; 5M+ total downloads; lightweight containers; headless compilation.
- **Status**: Active (v6.0.0-alpha.2)

### Spin (Fermyon)
- **Repo**: https://github.com/spinframework/spin
- **Stars**: ~5,200
- **Description**: Open-source framework for building and running fast, secure, composable cloud microservices with WebAssembly.
- **Agent Relevance**: Indirect (with emerging agent support)
- **Evidence**: Fermyon has published guides on building AI agents with Spin (including A2A protocol support, OpenAI Agents SDK in TypeScript). Sub-millisecond cold starts ideal for agent tool execution. CNCF Sandbox project.
- **Key Features**: Sub-millisecond cold starts; Component Model support; SDKs for JS, Rust, Go, Python; serverless deployment on Fermyon Cloud/Akamai; SpinKube for Kubernetes; A2A agent protocol support.
- **Status**: Active (Spin 3.0, CNCF Sandbox, acquired by Akamai)

### Extism (Dylibso)
- **Repo**: https://github.com/extism/extism
- **Stars**: ~5,430
- **Description**: Universal WebAssembly plugin framework — build extensible software with safe, sandboxed Wasm plugins.
- **Agent Relevance**: Indirect
- **Evidence**: Designed for executing arbitrary, untrusted code from users. Natural fit for agent tool/plugin systems. Supports 15 host languages and 8 guest languages. Used for extensibility in various products.
- **Key Features**: Persistent memory/module-scope variables; host-controlled HTTP (without WASI); runtime limiters & timers; PDK system for plugin authors; MIT license; 1.0 stable.
- **Status**: Active (v1.0.1)

### wazero
- **Repo**: https://github.com/tetratelabs/wazero
- **Stars**: ~5,100
- **Description**: The zero-dependency WebAssembly runtime for Go developers — pure Go, no CGO.
- **Agent Relevance**: Indirect
- **Evidence**: Used as the foundation for Timecraft (deterministic execution). Ideal for Go-based agent frameworks needing Wasm sandboxing without CGO dependencies. API stability promise.
- **Key Features**: Zero dependencies; pure Go; no CGO; cross-compilation support; Wasm Core Spec 1.0 & 2.0 compliant; interpreter and compiler modes; safe concurrency; context propagation.
- **Status**: Active (1.0+ stable)

### workerd (Cloudflare)
- **Repo**: https://github.com/cloudflare/workerd
- **Stars**: ~7,500
- **Description**: The JavaScript/Wasm server runtime that powers Cloudflare Workers — V8 isolate-based with Wasm support.
- **Agent Relevance**: Indirect
- **Evidence**: Powers Cloudflare Workers which are used for serverless AI functions. V8 isolate model provides sub-millisecond cold starts. Nanoservices architecture could host agent tools. WASI support since 2023.
- **Key Features**: V8 isolates; nanoservices architecture; standard web APIs (fetch, etc.); all built-in APIs in native code; Wasm + JS runtime; programmable HTTP proxy; C++ implementation.
- **Status**: Active (backed by Cloudflare)

## Tier 3: Distributed/Cloud Wasm Platforms

### wasmCloud (CNCF)
- **Repo**: https://github.com/wasmCloud/wasmCloud
- **Stars**: ~1,900
- **Description**: CNCF Incubating project enabling teams to build, manage, and scale polyglot Wasm apps across any cloud, K8s, or edge.
- **Agent Relevance**: Indirect (with direct agent sandboxing efforts via Cosmonic)
- **Evidence**: Cosmonic (wasmCloud's commercial backer) explicitly explores agent sandboxing with WebAssembly. Sandbox MCP plugin built on wasmCloud. Capability-based security model fits agent isolation. Used by American Express, Adobe, Akamai.
- **Key Features**: CNCF Incubating; Component Model (WASI 0.2); lattice mesh networking (NATS); Wadm declarative orchestration; OTEL observability; scale-to-zero; multi-cloud/edge deployment.
- **Status**: Active (v1.8.0, CNCF Incubating since Nov 2024)

### Golem Cloud
- **Repo**: https://github.com/golemcloud/golem
- **Stars**: ~964
- **Description**: Agent-native platform for building AI agents and distributed applications with durable computing on WebAssembly.
- **Agent Relevance**: Direct
- **Evidence**: Self-describes as "agent-native platform." Durable execution guarantees (exactly-once external calls, automatic crash recovery) directly address agent reliability. Supports golem:exec for durable code execution in JS/Python.
- **Key Features**: Durable computing (state survives failures/upgrades); exactly-once guarantees; WebAssembly Component Model; full execution traces; automatic recovery; language-agnostic (Rust, Go, JS/TS, Python via Wasm).
- **Status**: Active (open-source core, commercial cloud offering)

## Tier 4: Specialized/Embedded Wasm Runtimes

### WAMR (WebAssembly Micro Runtime)
- **Repo**: https://github.com/bytecodealliance/wasm-micro-runtime
- **Stars**: ~5,700
- **Description**: Lightweight standalone Wasm runtime with small footprint for embedded, IoT, edge, TEE, and cloud-native applications.
- **Agent Relevance**: Potential
- **Evidence**: Not directly used for agent sandboxing, but its small footprint and TEE support (Intel SGX) make it suitable for resource-constrained agent deployments. Supports remote application management from cloud.
- **Key Features**: Interpreter + Fast JIT + LLVM JIT + AOT; tiny footprint; SGX/TEE support; remote app management; platforms: Linux, macOS, Windows, Zephyr, NuttX, ESP-IDF, etc.; Apache 2.0 license.
- **Status**: Active (v2.4.4, Bytecode Alliance)

### wasmi
- **Repo**: https://github.com/wasmi-labs/wasmi
- **Stars**: ~2,000
- **Description**: Efficient and lightweight WebAssembly interpreter for embedded systems, originally from Parity for Substrate smart contracts.
- **Agent Relevance**: Potential
- **Evidence**: No direct agent use. Useful for agent sandboxing in constrained environments where a full JIT compiler is unnecessary. Can run inside Wasm itself (nested sandboxing). Used in Substrate/Polkadot blockchain.
- **Key Features**: Pure interpreter (no JIT needed); fuel metering; resumable function calls; 100% spec compliance; can run inside Wasm; mirrors Wasmtime API; low overhead.
- **Status**: Active (v0.32.0-beta)

### wasm3
- **Repo**: https://github.com/wasm3/wasm3
- **Stars**: ~7,800
- **Description**: Fast WebAssembly interpreter using novel M3 interpretation topology — the most universal WASM runtime.
- **Agent Relevance**: Potential
- **Evidence**: No direct agent use. Extremely portable (runs on microcontrollers, Arduino, ESP32). Could enable agent sandboxing on edge/IoT devices. Bindings for 12+ languages.
- **Key Features**: Novel M3 interpreter topology (3x faster than Lua); runs on 64KB Flash / 10KB RAM; supports x86, ARM, RISC-V, MIPS, Xtensa, ARC32; language bindings for Python, Rust, Go, Swift, etc.
- **Status**: Minimal maintenance (developer affected by war in Ukraine; reviewing/merging PRs only)

### WAVM
- **Repo**: https://github.com/WAVM/WAVM
- **Stars**: ~2,749
- **Description**: WebAssembly Virtual Machine using LLVM for near-native execution performance.
- **Agent Relevance**: Potential
- **Evidence**: No direct agent use. Near-native performance via LLVM compilation could benefit compute-heavy agent workloads. Strong isolation guarantees.
- **Key Features**: LLVM-based compilation; near-native performance; virtual memory + signal handlers for zero-cost bounds checking; prevents access outside Wasm VM; 64-bit hosts only.
- **Status**: Unmaintained (no commits in 1+ year)

### Lunatic
- **Repo**: https://github.com/lunatic-solutions/lunatic
- **Stars**: ~4,800
- **Description**: Erlang-inspired runtime for WebAssembly with preemptive scheduling, process isolation, and fine-grained resource control.
- **Agent Relevance**: Potential
- **Evidence**: Not directly used for agent sandboxing, but its process model (lightweight isolated processes with per-process resource limits) maps well to multi-agent architectures. Work-stealing async executor prevents blocking.
- **Key Features**: Preemptive scheduling; per-process fine-grained resource access (filesystem, memory, network); work-stealing executor; built on Wasmtime/Cranelift; Rust and AssemblyScript focus.
- **Status**: Stale (last release v0.13.2, May 2023; no indication of active development)

## Tier 5: Confidential/Privacy-Preserving Wasm

### Enarx
- **Repo**: https://github.com/enarx/enarx
- **Stars**: ~1,400
- **Description**: Confidential Computing with WebAssembly — run Wasm workloads inside Trusted Execution Environments (Intel SGX, AMD SEV-SNP).
- **Agent Relevance**: Potential
- **Evidence**: Not directly targeting AI agents, but confidential computing is relevant for privacy-sensitive agent workloads. CPU-architecture independent TEE deployment. Part of Linux Foundation's Confidential Computing Consortium.
- **Key Features**: Intel SGX + AMD SEV-SNP support; WebAssembly-based workloads; remote attestation; vendor-neutral TEE abstraction; multi-language support (Rust, C/C++, Go, Python, etc.).
- **Status**: Low activity (not archived, but limited recent development)

### Veracruz
- **Repo**: https://github.com/veracruz-project/veracruz
- **Stars**: ~198
- **Description**: Privacy-preserving collaborative computation using Wasm in TEEs (Arm TrustZone, Intel SGX, AWS Nitro Enclaves, seL4).
- **Agent Relevance**: Potential
- **Evidence**: Privacy-preserving ML is a key use case. Wasm acts as both sandbox and portability layer across TEE technologies. Could enable privacy-preserving multi-agent computations.
- **Key Features**: Multi-TEE support (TrustZone, SGX, Nitro, seL4); Wasm-based computation sandboxing; privacy-preserving ML use cases; CCC adopted project; custom SDK.
- **Status**: Archived (Feb 2026, transitioning to Emeritus stage of CCC)

## Tier 6: Standards & Specifications

### WASI (WebAssembly System Interface)
- **Repo**: https://github.com/WebAssembly/WASI
- **Stars**: ~4,900+
- **Description**: Capability-based system interface standard for WebAssembly, providing secure access to OS resources.
- **Agent Relevance**: Foundational
- **Evidence**: WASI's deny-by-default, capability-based security model is the foundation for all Wasm-based agent sandboxing. WASI 0.2 (Preview 2) now stable; WASI 0.3 adding async support (Feb 2026).
- **Key Features**: Capability-based security; deny-by-default; WIT interface definitions; worlds (wasi-cli, wasi-http, wasi-sockets, etc.); language-agnostic; Preview 2 stable.
- **Status**: Active (WASI 0.3 released Feb 2026)

### WebAssembly Component Model
- **Repo**: https://github.com/WebAssembly/component-model
- **Stars**: ~1,000+
- **Description**: Higher-level format for composable, interoperable Wasm modules with typed interfaces and cross-language communication.
- **Agent Relevance**: Foundational
- **Evidence**: Enables composable agent tools as portable components. Canonical ABI provides secure cross-language communication without direct memory access. Foundation for Wassette, wasmCloud, Spin, Golem.
- **Key Features**: WIT (WebAssembly Interface Types); Canonical ABI; cross-language composition; resource handles; string/vec lifting/lowering; virtualizability.
- **Status**: Active (being stabilized alongside WASI Preview 2)

### wasi-nn
- **Repo**: https://github.com/WebAssembly/wasi-nn
- **Stars**: ~535
- **Description**: Neural Network inference API proposal for WASI — enabling ML inference from WebAssembly using existing models.
- **Agent Relevance**: Indirect (enables AI in Wasm)
- **Evidence**: Allows agents running in Wasm to perform ML inference natively. Supported by Wasmtime (OpenVINO) and WasmEdge (TensorFlow, PyTorch, ONNX). Bridges the gap between Wasm sandboxing and AI capabilities.
- **Key Features**: Backend-agnostic (ONNX, TensorFlow, PyTorch, OpenVINO); CPU/GPU/TPU targets; portable ML deployment; graph/tensor abstractions; ease-of-use with existing models.
- **Status**: Active (proposal stage under WebAssembly org)

## Key Trends (2025-2026)

1. **MCP + Wasm convergence**: Wassette, Sandbox MCP, llm-wasm-sandbox, and mcp-run-python all combine WebAssembly sandboxing with MCP for standardized agent tool execution.
2. **Component Model maturity**: WASI Preview 2 and the Component Model enable composable, language-agnostic agent tools (Wassette, wasmCloud, Spin, Golem all use this).
3. **Sub-millisecond cold starts**: Wasm isolates start in microseconds vs. milliseconds for containers — critical for interactive agent tool invocation.
4. **Capability-based security**: Deny-by-default access control is the standard pattern, fitting naturally with agent authorization (what tools can an agent use?).
5. **Durable execution**: Golem Cloud brings durable computing to agent workloads — state persistence, exactly-once guarantees, and crash recovery without external infrastructure.
6. **GitHub MCP Registry**: GitHub launched MCP Registry with explicit Wasm support — publish AI tools as Wasm modules for any agent to download and run sandboxed.
